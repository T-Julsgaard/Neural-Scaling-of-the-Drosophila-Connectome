# EXP-003 development protocol 1.0

Specified before development execution, 2026-09-12. User authorization covers freezing and running development, not confirmation. R03 and the EXP-002 learning baseline remain immutable prerequisites. This addendum resolves campaign details under EXP-003 without changing its hypotheses or confirmation margins.

## Prospective scope and streams

Run ten independent development blocks 100–109, three nested graph replicates 0–2 per grown condition, all sizes 73,80,91,110,146 and 20 reset episodes of 384 trials. Episodes 0–9 are reversal and 10–19 interference, with EXP-002's schedules, chosen-action feedback, noise, probes and metric windows. Reset output weights to 0.1 every episode. No confirmation inputs are generated by the runner; reserve stage 2 blocks 1000–1019 for a later authorized campaign. Implementation tests use stage 0 blocks 0–4 only.

PCG64 streams use `SeedSequence([3,stage,block,domain,replicate,size,component,*suffix])`, with stage 0 validation or 1 development. Domain 0 gives task streams with replicate=size=0: component 1 native tie priority; 2 prototypes/order (suffix episode); 3 online noise (episode), or probe noise (episode,32,trial,round(sigma*1000)); 4 potential rewards (episode); 5 action uniforms (episode). Domain 1 gives graph streams with actual replicate/size: components 1 donors, 2 structured sampling, 3 uniform sampling, 4 degree swaps, 5 grown tie priority. Domain 1, size=0, component 6 generates the exploratory resampled native base, paired across sizes within each block/replicate. Domain 2, replicate=size=0, component 7 generates 10,000 paired block-bootstrap resamples. These streams are distinct from both earlier experiments' validation and EXP-002 development/confirmation.

All main growth algorithms, raw counts, donor allocation and tie interleaving follow R03. The existing validation implementation stays unchanged; the campaign wraps its reconstruction checks with translated metadata after validating the actual stage/block/node IDs. Native N=73 is evaluated once per block and reused across main arms/replicates. The whole-uniform exploratory arm resamples every native column with its original count multiset and degree, retains a common resampled base across sizes, and uses the same added columns as the main uniform arm. Its base has three real graph replicates, including at N=73. It preserves contact multisets, not native wiring. Explicit replacement columns and added-cell lineage are retained.

## Selection, controls and interpretation

Use generic delta, chosen previously using EXP-002 development. Run the nine pairs eta {0.0001,0.001,0.01} × temperature {0.1,0.2,0.5}. Score is the equal mean of acquisition (96–127), early reversal (128–159, reversal family), and post-interference A/B retention after update 256 (before return learning). Average episodes within family as specified by the baseline metrics, then graph replicates within each block/size/arm, then **equally weight the 20 main size/arm combinations**, then equally weight ten blocks. Native N=73 thus receives one fifth of size weight, despite baseline reuse. Select one shared pair; ties within 1e-6 prefer smaller eta then larger temperature. Do not tune individual architectures.

Run the same nine pairs for exploratory whole-uniform growth and the controls: fixed-four sparsity at N=110 clone/structured/null (native N=73 reuses its identical full result); 32-feature bottleneck at N=73 once and N=110 structured/null. These are excluded from shared selection. This produces 80 unique representation conditions per block: 49 main, 15 whole-uniform, 9 fixed-four and 7 bottleneck. Include a frozen native N=73 control (eta=0,T=.2) alongside its grid. The fixed EXP-002 eta=.01/T=.1 sensitivity is already in the grid and is reported alongside the shared selection without extra tuning.

Report all grid scores and selected-setting block-level profiles: acquisition, early reversal, return adaptation, pre/post-interference retention, robustness at noise 0,.1,.3, learning curves, and resources. Compare each arm's 110/146 against its own 73 baseline; compare structured versus degree null at 110. Graph replicates are nested, never independent task blocks. Use paired 95% block-bootstrap intervals as **descriptive development uncertainty**, including the organization comparison; the confirmatory 98.33% test remains unrun. No development interval establishes H3 or biological superiority because these blocks also select the setting. Preserve all arms regardless of their development ranking.

Record native/added participation, unused fractions, covariance participation rank and duplicate normalized input columns before any bottleneck; report bottleneck readout rank separately. Novelty does not imply useful learning. Fixed sparsity and bottleneck outcomes diagnose sensitivity to active-unit count and output parameter count. A poor development result is recorded rather than hidden or used to redraw seeds. Freeze the selected pair for potential confirmation; no automatic confirmation run is part of this task.

## Execution, validation and recovery

Validate fresh streams, schedules and pairing; exact encoding equivalence with the scalar R03 encoder (including ties and noise-free probes); no-growth identity across main arms; grown graph and whole-uniform invariants/reconstruction; scalar/batched update/probe agreement; nonmutating probes and graph/mode-bound checkpoint recovery. Check that selection weights sizes/arms correctly and excludes controls. Test interruption/recovery with deterministic episode replay and reject changed contracts or saved artifact hashes before development.

The faster encoder performs the same individual float64 matrix-vector products as R03 and batches only sorting, normalization checks and independent learner configurations. It must exactly match R03 activities on validation tasks. It does not approximate pre-activation values or change winner ties.

Freeze a digest-protected contract containing protocol/code/input hashes, environment, grid, conditions, seed domains and completed validation evidence before generating development inputs. Write each completed episode atomically, followed by a digest-protected condition checkpoint; interrupted episodes replay from their reset state. Do not rewrite completed episodes or final summaries. Resume verifies configuration, graph, environment, chronology and artifact hashes. Store per-trial scalar metrics, probes, final weights and aggregated feature moments, not full neural state per trial. Graph lineage and exogenous input digests remain recoverable.

Use up to three CPU worker processes on independent blocks; execution order cannot change streams or metrics. Retain compact summaries and manifest in Git; raw episode NPZ archives stay local with hashes. Stop on a numerical/invariant/mixing failure, fewer than 20 GiB free, 10 GiB retained artifacts, or seven days active campaign time. Never exclude an episode. Record errors and preserve partial state for recovery. Report current-session wall/CPU time, peak worker memory, retained bytes and dimensions; no energy estimate or claim about the colleague's workstation. Audit raw artifacts and recompute condition metrics and shared selection after completion.

Run `python tools/run_growth_development.py --workers 3`. The default destination is `results/exp003_development`; resuming uses its frozen contract and exact checkpoints. Validation and audit commands are `python tools/validate_growth_development.py` and `python tools/audit_growth_development.py`. Confirmation remains inaccessible through this runner.
